TriTopic 2.5 · demo run

What does TriTopic find in 1,000 BBC articles?

TriTopic 2.4 and BERTopic ran on the same 1,000 news articles with identical embeddings. The BBC files every article under one of five sections, so you can check how well the topics match the real structure. An LLM then reads TriTopic's topics, names them and repairs the ones that mix two themes. Further down: a run seeded from a codebook, and the research outputs TriTopic adds for a paper (reliability, saturation, bridges, group differences, a coding scheme, a second coder and the methods paragraph).

LLM interpretation

The LLM reads every topic

For each topic, TopicInterpreter gives the LLM the keywords, eight example articles that cover the topic in proportion, and the neighbouring topics. It answers with a label, a description and a verdict: one coherent theme, or a mix. These are its verdicts on TriTopic's automatic run.

Automatic mode

How TriTopic picks the number of topics

Without a target, TriTopic tries 15 resolutions. For each one it extracts keywords and measures how often these words appear together in articles (NPMI coherence). It keeps the coarsest resolution whose coherence is within 5% of the best.

The number above each point is the topic count at that resolution. The amber point is the automatic choice.

Codebook mode

Start from the categories you expect

With fit(documents, seeds={...}) you describe the topics you expect in a sentence each. The articles that fit a description best are pinned to one topic per seed; all other articles can join a seeded topic or form new ones. Here once with all five BBC sections, and once with only three of them, so the other two have to emerge on their own.

Reliability

Which topics can you trust?

TriTopic refits the model on five random 80% samples and checks how well each topic reappears (Jaccard overlap). On four benchmark corpora, topics above 0.7 were 77% pure against the true classes, topics below 0.5 only 54%. Core share = articles that stay in the topic in at least 90% of the refits.

Saturation

Have we seen every topic?

If you read the articles in random order, when does each topic have enough articles (at least five) to be found? The curve is exact (hypergeometric), the topic accumulation curve known from ecology and the "no new codes in the last interviews" criterion of qualitative research.

Topic evolution · real dated news

What was new, year by year?

The BBC articles carry no dates, so this part uses another corpus: . topic_evolution(model, dates, freq="Y") clusters every year on its own, finer than the global model, and links topics of consecutive years when their centroids are similar (cosine ≥ 0.75). A topic without a predecessor is a birth. Nobody told the model about any event.

Codebook for manual coding

A coding scheme, written from the topics

TopicInterpreter.codebook() writes a category per topic in the style of qualitative content analysis: definition, inclusion and exclusion criteria (naming the neighbouring category to use instead) and coding notes. The anchor examples are real sentences from the articles, picked by topic_quotes(), not generated text.

Takeaways

What this run shows

Data: BBC News test split (SetFit/bbc-news), 1,000 articles, words on average. Embeddings: all-MiniLM-L6-v2, identical for all models. Seed 42. TriTopic 2.5.1 · BERTopic 0.17.4 ("tuned" = stop words, bigrams, reduce_frequent_words) · LLM: gpt-6-luna via the OpenAI Responses and Decisions APIs ( requests). One run with one seed, and LLM answers vary between runs. The robust numbers over four datasets and three seeds are in the README benchmarks.
